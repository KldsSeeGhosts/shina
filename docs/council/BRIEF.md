# Shina design council brief

You are one judge on a design council reviewing Shina, a native desktop chat workspace for the Pi coding agent, written in Rust with the Rune GPU UI toolkit (pre-release, pinned git rev). Repo: `D:\AiStack\shina`. The UI is drawn in `src/ui.rs`, state in `src/model.rs`. Capy is the design reference the owner admires.

This council runs a hill climb: each round, Shina changes and judges re-score it against the same baseline.

## Rules

- READ-ONLY. Do not edit, create, or delete any file in the repo. Do not run `cargo build` or other commands that write to `target/`. Do not commit. Do not spawn subagents.
- Open the PNG screenshots listed in your task and read `src/ui.rs` as needed so recommendations are concrete (cite functions and line numbers in the current file).
- The captain portraits (Ember, Juniper, Sable, Pip) are original pixel art generated by `tools/crew_originals.py`, in the style of Pokemon Mystery Dungeon portraits on Capy-style colored tiles. They are in scope: judge readability at 16/20/24/40px, expression legibility, palette fit with the UI, and consistency across the four. `crew-sheet.png` in the round folder shows all six expressions per captain (Ready, Settled, Working, Needs you, Failed, Offline). Earlier rounds used a different placeholder set; judge only the current art.
- "Demo" labels are intentional: the screenshots use a read-only demo workspace.
- No web search needed.

## Output (your final message, markdown, under ~900 words)

1. One comparison table, 0-10 with one decimal. Rows: Typography, Hierarchy, Spacing & density, Color & contrast, Iconography, Consistency & polish, Clarity, Overall. Columns, in this order: **Shina baseline** (`r0/`), **Shina previous** (the previous round folder named in your task), **Shina current** (the current round folder named in your task), **Capy** (`refs/capy.png`, a live Capy window, dark theme). Add one extra row, **Crew art**, scored for Shina previous, Shina current, and Capy only. Score every column on the same scale so the table is a stable baseline across rounds. Judge Capy only on what its screenshot shows.
2. Verdict: does the current round approve as a noticeable improvement over the previous round? (yes/no, one sentence.)
3. Top 3 remaining gaps between Shina current and Capy (one line each).
4. Up to 6 prioritized, concrete changes for the next round. For each: what is wrong (screenshot evidence), the exact fix (sizes, hex colors, spacing in px, function in ui.rs), and expected impact. Order by impact per effort. Do not repeat a change that is already done.
5. Any visibly broken or misleading UI element that remains.
